# NV: результаты аудита, восстановления и дальнейший план

Дата: 30 сентября 2026. Исходный Git-снимок `15891165d975ab202a0fbd795de0a115521d2700` опубликован в GitHub до начала переработки. Текущие изменения находятся в рабочей папке; этот отчёт не объявляет их коммерческим релизом.

## 1. Почему клиент работал плохо

Обнаружены несколько разных причин, требующих разных исправлений.

**Неработающие функции.** Наличие модуля, настроек и файла шейдера не означало наличие отрисовки. У HitBubbles, Ripple в JumpCircle, стеклянных Trails, насыщенности и эффектов убийства конечные renderer-методы были пустыми. У Shader ESP конечный метод остаётся пустым. Перетаскивание HUD тоже вызывало пустые методы ограничения и привязки. Это прямые функциональные дефекты, а не предположение о низком FPS.

**Ошибки жизненного цикла.** Неуспешное включение модуля оставляло подписку и enabled; исключение при выключении мешало очистке; повторный init/subscribe создавал дубликаты. Отпускание HOLD при открытом GUI могло потеряться. Асинхронная обложка могла вернуться после сброса, а сетевые callbacks — после disconnect.

**Непроверенная совместимость с версией.** Некоторые mixin targets не соответствовали mapped API Minecraft 1.21.11, при этом optional require скрывал отсутствие внедрения. Version metadata допускал лишние версии. NightConfig был продублирован в metadata.

**Вырезанный и несовместимый backend.** Старый NV-сервис не реализовывал три визуальных sync-канала, часть команд Party и безопасную изоляцию личных сообщений. Перенос старого файла на VDS не исправил бы протокол: потребовалась новая реализация и согласование клиента.

**Затраты рендера.** Много проходов неба, scene copies, live edge/refraction, крупный UI-класс, culling на render thread — кандидаты для профилирования. Само число проходов не доказывает их вклад в FPS. Измеренная длительность Java render-call и полный GPU frametime — разные показатели.

Полный исходный аудит, приоритеты, таблица всех 69 зарегистрированных функций и сравнение с GitHub: [AUDIT-2026-09-29.md](AUDIT-2026-09-29.md). В продукте скрыт TestSettings, поэтому пользовательский каталог содержит 68 модулей. Таблица задаёт приёмку каждой функции; lifecycle sweep не заменяет её.

## 2. Что реально изменено

### Надёжность

- Module lifecycle получает откат включения и unsubscribe в finally; EventBus идемпотентен по владельцу и публикует готовый список обработчиков.
- Реестр модулей защищён от повторного init, поиск по типу кешируется; HOLD release обрабатывается при открытом GUI, удержание сбрасывается при утрате игрового контекста.
- Конфиги, профили и темы сохраняются через временный файл, fsync и atomic replace с запасным вариантом. Записи в один путь сериализованы; временная Windows-блокировка rename получает ограниченный retry. Полное повреждение диска или бессрочная блокировка не скрываются как успех.
- Исправлены актуальные mixin targets и checked-version metadata. Версия продукта разворачивается из Gradle; вложения NightConfig теперь перечисляются один раз.
- Music helper стартует в фоне и имеет контролируемый shutdown. Обложки ограничены размером и очередью, stale-generation не восстанавливает старую текстуру; HTTP ответы и lyrics ограничены.
- Сетевые буферы, очереди и списки состояний ограничены. Epoch защищает от callbacks старого соединения. Presence не показывает бессрочно устаревший кеш.

### Визуал

- Glass получил более спокойный фон и меньшую интенсивность преломления; Mosaic — собственную прямоугольную структуру и более устойчивый фон под текстом. Live edge и contouring сохранены.
- Добавлены общие UI tokens, шрифтовые алиасы на Montserrat, кеш палитры внутри кадра. SF Pro исключён из product resources.
- Ширина dock учитывает inspector и доступный viewport. Проверены окна 854×480, 1280×720 и 1920×1080. Это не подтверждает все DPI/GUI-scale сочетания и 4K.
- HitBubbles, Jump Ripple, стеклянные Trails, насыщенность, Kill Scan и Kill Distortion теперь создают реальные GPU-проходы. Общий FullscreenPostPass ограничивает uniform storage, переиспользует texture/buffer, освобождает их при shutdown/reload и допускает восстановление после ошибки.
- Target Circle рисует многослойную геометрию вместо пустой прослойки; обработка through-walls исправлена также для AuraGlow.
- Восстановлены ограничение HUD по экрану, привязка к центру/краям и outline. Проверены перенос и отмена с возвратом начальной позиции.
- Исправлены направления и ненулевые размеры shards/ribbons/sparks в Trails. Удалён пустой build и неиспользуемый SaturationRenderer. Дальнейшую художественную настройку Trails выделить отдельно: наличие draw не гарантирует выразительность изображения.
- Вместо WaveyCapes используется собственная аналитическая сетка плаща: 12 сегментов, около 200 вершин. Сторонний код архивирован локально и исключён из активной сборки.
- Созданы оригинальные модели, текстуры и flight-анимации духа, мини-дракона и мотылька. Модель теперь получает угол сущности; дефект импортированного Gecko bridge, из-за которого питомец визуально не поворачивался, исправлен в CustomPetRenderer.
- Удалённые GUI получили реальный anchor, интерполяцию угла/scroll и завершение fade при закрытии. Переходы категории, поочерёдное появление строк и shatter пока упрощены.

### Сетевые функции

На предоставленном VDS восстановлен собственный backend IRC/Party/Globals. Публичный путь — `https://virion.185-56-162-195.sslip.io/nv`. Авторизация установки общая для HTTP и трёх WSS sync-клиентов.

Проверены изоляция PM, серверное назначение отправителя, ownership приглашения, запрет disband для обычного участника, kick, reconnect, передача лидерства, миры/комнаты и удаление исчезнувших visual states. Java-клиент также прошёл живой обмен через TLS.

Сервис работает от `nv-social` в собственном Python-окружении. Backend слушает localhost, Nginx принимает HTTPS/WSS. SQLite хранит установки, IRC и Party. Оригинальный код, unit, Nginx и старое IRC сохранены в ограниченной резервной копии. Сравнение прежнего и текущего Virion virtual host показало только добавление include NV и пустой строки; остальные location сохранены.

Подробности протокола, ограничения, обновление и откат: [backend README](../backend/README.md). SSH-ключ использовался только локально как файл аутентификации; его содержимое не читалось и не включалось в артефакты.

## 4. План по всем функциям и UX-приёмка

В [таблице исходного аудита](AUDIT-2026-09-29.md#4-план-по-каждой-функции) перечислены все зарегистрированные функции. Ни одна не считается полностью принятой только по успешному enable/disable. Рабочая последовательность для каждой: воспроизвести смысловое действие → проверить настройку → проверить отключение → сохранить/загрузить → сменить мир/сервер → проверить удержание/фокус, если есть input → проверить reload, если есть render resources.

Первый проход следующей реализации:

1. **Shader ESP и сеть.** Закрыть подтверждённую пустую отрисовку, реальную принадлежность профиля и приватные комнаты. Голос оформлять отдельной функцией с собственным критерием, сейчас он недоступен.
2. **TargetHUD, HPFocus, TargetESP, NameTags, SelfTag, HP counter.** Проверить живую цель, absorption, смерть, смену цели, spectator, расстояние и стену; использовать один понятный цвет hurt/health, устойчивый empty state. Не показывать старое здоровье после исчезновения цели.
3. **Notifications, ArrayList, HotKeys, Info, Scoreboard, Music HUD.** Проверить длинный русский текст, многократные события и очередь; обновлять данные по событиям/таймеру, а не пересортировывать неизменный список каждый draw. Empty/offline состояния должны быть нормальными состояниями UI.
4. **Hotbar, Inventory, Armor, Cooldowns, Potions, KeyStrokes.** Одна сетка и размеры иконок; пустые слоты и истёкшие таймеры не резервируют случайное место; mouse/key state сбрасывается при потере фокуса. Тестировать drag с переключением scale и маленьким окном.
5. **CameraSettings, Freelook, ViewModel, HandSwap, SwingAnimation, AspectRatio, Crosshair, ShaderHands.** Сочетания, main/offhand, FOV, first/third person, use-item, HOLD и aspect. Любая настройка должна возвращать исходное поведение после отключения.
6. **Ambience, FogBlur, NoRender, Optimization, culling.** Проверять отдельно собственное небо, погоду/время, туман и каждый флаг скрытия. Nether/End, shader pack и внешний culling не должны оставлять исчезнувшие объекты или менять флаги соседнего модуля. Пресеты экономии объясняют, что теряется в качестве.
7. **HitColor, Hitboxes, HitParticles, WorldParticles, HitBubbles, JumpCircle, KillEffect, Trails, ChinaHat, BlockOverlay, ItemPhysics/Highlight.** Смысловой trigger, реальный объект в кадре, depth, frustum/distance, bounded lifetime и cleanup. Проверять худший обычный сценарий: серия ударов, много drops, длительный спринт, частые прыжки.
8. **Pets, Emotions, FakePlayer.** Оригинальные персонажи должны читаться с бокового и переднего ракурса, не закрывать прицел, останавливаться и плавно догонять. FakePlayer исчезает после выключения/смены мира; emotion bridge проверяется настоящей анимацией, а не только получением пакета.
9. **Predictions, ProjectileHelper, ShulkerPreview и BetterMinecraft.** Каждое предсказание привязывается к фактической траектории, каждый container tooltip учитывает компонентный API версии; каждый встроенный компонент отдельно проверяется на конфликт с внешним аналогом.
10. **AutoDuel, AutoCommands, FastExp, ItemScroller, TapeMouse, TalTracker, DeathCoords, StreamerMode, Discord, ClientSounds/HitSound.** Действие не повторяется каждый tick, имеет ограничение частоты и отмену; имя/адрес не раскрываются другим HUD/sharing; звуковые ресурсы проверяются по реальному event, а не только наличию файла.

Общие правила визуала: у Glass спокойная основа и ограниченные highlights; у Mosaic геометрический рисунок отделён от text zone; tooltip непрозрачнее художественного фона; on/off/disabled различимы не только оттенком; длинные названия не выходят за hitbox. Общие токены должны доходить до HUD и popup, а не оставаться только в главном dock.

В логах присутствуют намеренные исключения regression fixture; они подтверждают проверку rollback. Realms использует тестовую Fabric-сессию и не авторизуется. Предупреждение `ThemeWaveParams` требует отдельной очистки объявлений uniform: успешный запуск не означает, что все декоративные параметры применяются. Во время lifecycle sweep AutoDuel получил отказ тестового vanilla-сервера на его команду — это не проверка поддерживаемого реального сервера.

## 6. Производительность

До/после снимались отдельно, на одинаковой тестовой плоской сцене: 1280×720, view distance 2, GUI scale 2, лимит 120 FPS, VSync off; прогрев мира и каждой сцены. Исходный snapshot запущен в отдельном checkout, новый — отдельным benchmark suite. Около 1750–1790 samples на общий сценарий. Реальных game processes параллельно benchmark не запускалось.

Метрика — длительность вызова `GameRenderer.render` на основном потоке через `System.nanoTime`. Она включает ожидание внутри этого вызова, не является аппаратным CPU-счётчиком, полным frame pacing или GPU timestamp. Не вычислять из неё FPS/1% low. Значения из более раннего `after-production-preliminary.csv` относятся к иной конфигурации и не используются для вывода до/после.

|---|---|---|---|
| Мир | 0.3414 → 0.3251 | 0.7139 → 0.5660 | 1.0126 → 0.7296 |
| GUI Glass | 0.8967 → 0.9529 | 1.7482 → 1.5530 | 2.9243 → 1.8114 |
| GUI Mosaic | 0.7936 → 0.9019 | 1.5092 → 1.4318 | 2.5612 → 1.7339 |
| Северное сияние | 0.6550 → 0.7121 | 1.2827 → 1.2796 | 1.8138 → 1.6270 |

| Звездопад | 0.7517 → 0.6911 | 1.4499 → 1.2287 | 2.1268 → 1.6312 |

**Средний по порядку кадр GUI стал дороже:** median Glass примерно +6%, Mosaic +14%. В этом прогоне тяжёлый хвост GUI улучшился: p99 Glass примерно −38%, Mosaic −32%. Black hole показал снижение median render-call примерно на 35%; этому нельзя приписывать такой же прирост FPS.

Default нового неба — Balanced, а исходное качество фиксировано. В CSV отдельно есть High нового renderer: это помогает видеть влияние качества, но одного прогона без GPU timing недостаточно для разделения всех причин. Это измеренный результат одной сцены, не обещание на любой карте и машине. Для следующего этапа: A/B несколько прогонов на нагруженной multiplayer-сцене, полные frame intervals, CPU/GPU timings и counts draw/copy/pass. Сначала выявить bottleneck, затем выбирать blur sharing, culling worker или batching.

## 7. Порядок дальнейшей работы

1. Восстановить Shader ESP и подтвердить смысловые triggers перечисленных эффектов на настоящем сервере.
2. Закрыть identity/room trust и лицензионные вопросы, которые влияют на заявленный коммерческий продукт.
3. Довести HUD/inspector/popups и художественную читабельность pets/Trails; выполнить всю функциональную таблицу приёмки.
4. Проверить чистый клиент, поддерживаемые renderer/emote mods, resize/fullscreen/alt-tab и два игрока.
5. Измерить обычную и тяжёлую сцену несколько раз. Оптимизировать найденный bottleneck, сохраняя качество и обратимость.
6. После этого сформировать версионированный релиз с точными зависимостями, notices, migration/rollback и пользовательской инструкцией.
